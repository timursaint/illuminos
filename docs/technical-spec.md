## 2. Назначение и цели создания системы

### 2.1. Назначение
Система предназначена для предоставления пользователям доступа к каталогу фильмов
и сериалов, оформления подписки и просмотра контента, а также для управления
каталогом и заказами со стороны администратора.

### 2.2. Цели создания
1. Дать зрителю единую точку входа: каталог, поиск, карточки тайтлов, личный кабинет.
2. Автоматизировать продажу подписок: тарифы, промокоды, оплата, учёт платежей.
3. Сократить время сотрудника на управление каталогом за счёт админ-панели.
4. Собрать данные о предпочтениях (избранное, история, оценки) для рекомендаций.

### 2.3. Целевая аудитория
- **Гость** — просматривает каталог, карточки, трейлеры; не может смотреть фильмы целиком.
- **Пользователь** — зарегистрирован, ведёт избранное, историю, оценки; подписки нет.
- **Подписчик** — оплатил тариф, имеет доступ к просмотру.
- **Администратор** — управляет каталогом, категориями, пользователями и заказами.

## 3. Характеристика объекта автоматизации

Объект — онлайн-кинотеатр с собственной библиотекой контента (фильмы и сериалы).
Текущие процессы: подбор контента вручную, продажа подписок через переписку,
отсутствие единого каталога и истории просмотра. Система переводит эти процессы
в веб-среду: каталог с фильтрами, личный кабинет, оплата и админ-панель.

Ограничения учебного проекта: платёжный шлюз эмулируется, видеоконтент —
локальные демонстрационные файлы, хостинг — локальный веб-сервер OpenServer Panel.

## 4. Требования к системе

### 4.1. Требования к системе в целом

#### 4.1.1. Структура и функционирование
Система строится по клиент-серверной архитектуре:
- **клиент** — браузер (HTML5, CSS3, JavaScript, Bootstrap 5);
- **сервер** — Apache/Nginx + PHP 8.1;
- **СУБД** — MySQL 8.0 / MariaDB 10.6, кодировка utf8mb4;
- **взаимодействие** — HTTP-запросы, серверный рендеринг PHP, AJAX для динамических блоков.

Модули: главная страница, каталог/поиск, страница тайтла, регистрация и авторизация,
личный кабинет, тарифы и оплата, админ-панель, API-слой (`api/*.php`).

#### 4.1.2. Требования к пользователям
Одновременная работа не менее 50 пользователей; три роли доступа
(администратор, подписчик, пользователь) с разграничением прав на уровне сессий и запросов.

#### 4.1.3. Показатели назначения
- Время отклика страницы каталога — не более 2 с при 1 000 тайтлов.
- Поиск с подсказками — не более 500 мс после ввода.
- Каталог — не менее 8 жанров, фильтрация по типу, жанру, году, сортировка.

#### 4.1.4. Требования к надёжности
- Сохранность данных при перезапуске сервера (InnoDB, транзакции при оплате).
- Валидация всех входных данных на клиенте и сервере.
- Понятные сообщения об ошибках вместо «белого экрана».

#### 4.1.5. Требования к безопасности
- Пароли хранятся только в виде хеша `password_hash()` (bcrypt).
- Авторизация через сессии; `session_regenerate_id()` после входа.
- Защита от SQL-инъекций — подготовленные запросы PDO.
- Защита от XSS — экранирование вывода `htmlspecialchars()`.
- CSRF-токены для всех POST-форм.
- Разграничение доступа: `require_auth()` / `require_admin()`.
- Номер банковской карты не сохраняется, хранится только маска `**** 1234`.

#### 4.1.6. Требования к эргономике и технической эстетике
- Единая тёмная тема, акцентный цвет `#FF6B35`, контраст текста не ниже AA.
- Адаптивная вёрстка: мобильные (360–640), планшеты (641–1024), десктоп (1025+).
- Единая дизайн-система: токены цветов, компоненты, состояния hover/focus/disabled.

#### 4.1.7. Требования к эксплуатации
- Развёртывание на OpenServer Panel: импорт `database/illuminos.sql`, размещение
  проекта в `domains/localhost/illuminos`.
- Резервное копирование — экспорт БД через phpMyAdmin.
- Работа в браузерах Chrome, Edge, Firefox, Opera последних версий.

### 4.2. Требования к функциям (по подсистемам)

#### 4.2.1. Главная страница
1. Hero-баннер с 5 актуальными тайтлами и переключением без перезагрузки.
2. Блок «Новинки» — горизонтальная лента.
3. Блок «Популярное» — сетка карточек.
4. Блок «Категории» — 8 жанров с иконками и количеством тайтлов.
5. Блок персональных рекомендаций (для гостя — по рейтингу).
6. Блок «Продолжить просмотр» — для авторизованных.
7. Живой поиск в шапке с выпадающими результатами.

#### 4.2.2. Каталог
1. Поиск по названию, актёрам, режиссёру.
2. Фильтры: тип (фильм/сериал), жанр, год, сортировка.
3. Пагинация по 24 записи.
4. Отдельные страницы «Фильмы» и «Сериалы».

#### 4.2.3. Страница тайтла
1. Постер, название, оригинальное название, метаданные, описание.
2. Оценка Кинопоиска, средняя оценка зрителей, собственная оценка 1–10.
3. Режиссёр и список актёров.
4. Трейлер в модальном плеере.
5. Для сериала — сезоны и список серий (аккордеон).
6. Похожие тайтлы.
7. Отзывы и форма отзыва.
8. Кнопка «Смотреть» — только при активной подписке.

#### 4.2.4. Регистрация и авторизация
1. Поля регистрации: фамилия, имя, отчество, логин, e-mail, пароль, повтор пароля,
   согласие с правилами.
2. Валидация без перезагрузки страницы, сообщения под полями.
3. Уникальность логина и e-mail.
4. Авторизация по логину или e-mail через сессии.
5. Три роли: администратор, подписчик, пользователь.

#### 4.2.5. Личный кабинет
1. Статистика: просмотрено, избранное, оценки, подписка.
2. История просмотра с прогрессом.
3. Избранное с возможностью удаления.
4. Мои оценки и отзывы.
5. Подписка: срок действия и история платежей.
6. Редактирование профиля и загрузка аватара.

#### 4.2.6. Тарифы и оплата
1. Перечень тарифов с ценой, сроком, качеством и возможностями.
2. Сравнительная таблица тарифов.
3. Промокоды со скидкой (проверка на сервере).
4. Способы оплаты: карта, СБП, электронный кошелёк.
5. Формирование заказа, активация подписки, страница-чек.
6. Эмуляция платёжного шлюза (учебный режим).

#### 4.2.7. Корзина и покупка фильмов
1. Добавление фильма в корзину с карточки и со страницы тайтла (без перезагрузки).
2. Просмотр корзины: постер, название, цена, количество лицензий.
3. Редактирование корзины: изменение количества (1–5), удаление позиции, очистка.
4. Оформление заказа из корзины с выбором способа оплаты и промокодом.
5. После оплаты фильм становится доступен без подписки («Мои покупки»).
6. Заказ фильмов отображается в истории платежей и в админ-панели.

#### 4.2.8. Админ-панель
1. Дашборд: количество тайтлов, пользователей, выручка, заказы.
2. CRUD тайтлов: добавление, редактирование, удаление, загрузка постера, цена покупки.
3. Управление жанрами.
4. Управление сезонами и сериями.
5. Просмотр всех заказов (подписки и фильмы) и смена статусов
   (оплачен, ожидает, отменён, возврат) с пересчётом доступа.
6. Управление пользователями: роли и блокировка.
7. Управление промокодами.

### 4.3. Требования к видам обеспечения

#### 4.3.1. Математическое обеспечение
Расчёт скидки по промокоду: `скидка = цена × процент / 100`;
итог: `итого = цена − скидка`; срок подписки: `конец = начало + период − 1 день`;
при продлении: `новое начало = конец текущей подписки + 1 день`;
сумма корзины: `итого = Σ(цена фильма × количество лицензий)`.

#### 4.3.2. Информационное обеспечение
Реляционная БД `illuminos`, 16 таблиц: `users`, `genres`, `titles`, `title_genres`,
`seasons`, `episodes`, `favorites`, `watch_history`, `reviews`, `tariffs`,
`payments`, `subscriptions`, `promocodes`, `cart_items`, `order_items`, `purchases`.
Связи: «многие ко многим» тайтлы–жанры; «один ко многим» тайтл–сезоны–серии,
пользователь–платежи–подписки, заказ–позиции, пользователь–покупки.
Полная схема — `database/schema.sql`, миграция — `database/migrations/2026_11_cart.sql`.

#### 4.3.3. Лингвистическое обеспечение
Интерфейс на русском языке. Кодировка UTF-8 (utf8mb4). Термины: тайтл, подписка,
тариф, сезон, серия, избранное, промокод, корзина, лицензия, покупка.

#### 4.3.4. Программное обеспечение
PHP 8.1, MySQL/MariaDB, Apache, Bootstrap 5.3 (локальная копия), нативный JavaScript,
PDO, phpMyAdmin для администрирования БД.

#### 4.3.5. Техническое обеспечение
Персональный компьютер (Windows 10/11, 8 ГБ ОЗУ), локальный веб-сервер OpenServer Panel,
браузер. Для эксплуатации — веб-сервер с PHP 8.1+ и MySQL 8.0+.

#### 4.3.6. Организационное обеспечение
Роли и права описаны в п. 2.3 и 4.2.7. Администратор проходит инструктаж по работе
с админ-панелью (раздел «Эксплуатация» в README).

2. Создать БД `illuminos`, импортировать `database/illuminos.sql`.

5. Сменить демонстрационные пароли перед публикацией в интернет.
